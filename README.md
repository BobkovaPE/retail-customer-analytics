# Retail Customer Analytics

Данный проект направлен на решение следующего бизнес вопроса: какую аудиторию выбрать для кампании повторных покупок и чем обосновать выбор?

## Результаты

- Ноябрь к октябрю: положительные товарные продажи +31,72%, заказы +37,21%, AOV −4,00%
- Retention M1 января–октября — 19,73%; повтор за 30 дней после первой наблюдаемой покупки — 17,73%
- Верхние 20% известных клиентов дали 73,95% их положительных продаж; RFM выделяет 269 недавних однократных клиентов
- Для гипотезы письма на 14-е сутки ориентир пересчитан: 485/2 666 = 18,19%. При сценарии +5 п.п., α = 0,05 и мощности 80% нужно 2 060 участников

## Запуск

Стек: Python 3.12, pandas, NumPy, SQLite/SQL, matplotlib/seaborn, openpyxl. Основные расчётные версии зафиксированы в requirements.txt. SQLite входит в Python. Из папки проекта, macOS/Linux:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/run_pipeline.py
```

Команда выполняет обычный Python-код ячеек 01 → 02 → 03, с отдельным пространством переменных для каждого ноутбука, и сохраняет реальные текстовые выводы и PNG графиков. Для интерактивной работы откройте ноутбуки в Jupyter/VS Code и запускайте в том же порядке.

Если SQLite уже есть: `python scripts/run_pipeline.py --analysis-only`. Можно запускать скрипт из другой папки через его полный путь. Расчётные таблицы и графики обновляются при выполнении, редактировать результаты вручную не следует.

Архив содержит исходный Excel, SQLite и все результаты. С присутствующим Excel расчёты работают без сети. В компактном Git-репозитории Excel и база исключены: при отсутствии Excel подготовка скачивает официальный UCI-архив и проверяет SHA-256. Для первой установки зависимостей нужен доступ к пакетному индексу.

SQLite сначала собирается в памяти, затем записывается в отдельный временный файл в data/processed. Для полной пересборки требуется больше памяти, чем для чтения готовой базы. Готовая база заменяется после проверок. Не запускайте две полные сборки одновременно: выходные CSV и ноутбуки общие.

## Определения и структура

| Папка | Содержание |
| --- | --- |
| data/raw | Исходный Excel, описание и источник с SHA-256 |
| data/processed | retail.sqlite и описание таблиц |
| notebooks | Три последовательных выполненных ноутбука |
| sql | Семь запросов: заказы, KPI, клиенты, когорты и окна повторной покупки |
| scripts | Запуск всей цепочки из терминала |
| reports | Итоговый отчёт, аудит, JSON-контроли, CSV и восемь графиков PNG/SVG |
| docs | Постановка, решения, протокол и описание для портфолио |

SQLite: raw_transactions — исходные поля и номер строки Excel; transaction_audit — все строки с правилами отбора; purchase_lines — положительные товарные позиции; orders — одна строка на счёт; customer_orders, excluded_lines, cancellation_lines — представления.
